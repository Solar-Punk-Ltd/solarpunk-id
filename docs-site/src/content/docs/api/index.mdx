The `SwarmIdClient` is the main class for integrating Swarm ID authentication and storage capabilities into web applications. It enables parent windows to interact with a Swarm ID iframe proxy, providing secure authentication, identity management, and data upload/download functionality to the Swarm decentralized storage network.

## Installation

The library is `@solarpunkltd/swarm-id` on npm, installed as [Quick Start](../getting-started/#install)
shows. `@snaha/swarm-id` on npm is snaha's upstream package, without this fork's changes.

## Quick Start

```typescript
import { SwarmIdClient } from '@solarpunkltd/swarm-id'

const client = new SwarmIdClient({
  iframeOrigin: 'https://swarm-id.example.com',
  metadata: {
    name: 'My App',
    description: 'A decentralized application',
  },
  onConnectionChange: (info) => {
    console.log('Connection changed:', info.identity?.name, 'canUpload=', info.canUpload)
  },
})

await client.initialize()

// Show Swarm ID's sign-in button where your page has room for it
client.mountButton(document.getElementById('sign-in')!, { action: 'sign-in' })

// Read current connection state and upload if authenticated.
// Check `canUpload` too — an authenticated user can still lack upload
// capability (no postage stamp, no subsidised gateway).
if (client.connectionInfo?.identity && client.connectionInfo.canUpload) {
  const result = await client.uploadData(new Uint8Array([1, 2, 3]))
  console.log('Uploaded with reference:', result.reference)
}
```

## Constructor

### `new SwarmIdClient(options)`

Creates a new SwarmIdClient instance.

**Parameters:**

| Parameter                       | Type                             | Required | Description                                                                                                                                                                                                                                                                                                     |
| ------------------------------- | -------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `options.iframeOrigin`          | `string`                         | Yes      | The origin URL where the Swarm ID proxy iframe is hosted                                                                                                                                                                                                                                                        |
| `options.iframePath`            | `string`                         | No       | The path to the proxy iframe (defaults to `"/proxy"`)                                                                                                                                                                                                                                                           |
| `options.timeout`               | `number`                         | No       | Request timeout in milliseconds (defaults to `30000`). Bounds each call's whole round trip through the iframe; a call's own `requestOptions.timeout` replaces it for that call                                                                                                                                  |
| `options.initializationTimeout` | `number`                         | No       | Initialization timeout in milliseconds (defaults to `30000`)                                                                                                                                                                                                                                                    |
| `options.onConnectionChange`    | `(info: ConnectionInfo) => void` | No       | Callback invoked when the app-visible connection state changes (identity, app key, postage stamp, account, auth). The current snapshot is also available synchronously via `client.connectionInfo`.                                                                                                             |
| `options.popupMode`             | `"popup" \| "window"`            | No       | How the connect window opens, from a mounted button or `connect()` (defaults to `"window"`)                                                                                                                                                                                                                     |
| `options.metadata`              | `AppMetadata`                    | Yes      | Application metadata shown to users during authentication                                                                                                                                                                                                                                                       |
| `options.metadata.name`         | `string`                         | Yes      | Application name (1-100 characters)                                                                                                                                                                                                                                                                             |
| `options.metadata.description`  | `string`                         | No       | Application description (max 500 characters)                                                                                                                                                                                                                                                                    |
| `options.metadata.icon`         | `string`                         | No       | Application icon as a data URL (SVG or PNG, max 4KB)                                                                                                                                                                                                                                                            |
| `options.subsidisedGatewayUrl`  | `string`                         | No       | URL of a subsidised gateway for uploads without user's postage stamp. See [Subsidised Gateway](../subsidised-gateway/) for details.                                                                                                                                                                             |
| `options.beeApiUrl`             | `string`                         | No       | The Bee node this site's content reads and stamped uploads go through, in place of the node the person set in Swarm ID. The person's account and device coordination stay on their own node. Change it later with [`setBeeApiUrl()`](#setbeeapiurlurl). See [The site's own Bee node](#the-sites-own-bee-node). |

**Throws:**

- `invalid-request` if the provided app metadata is invalid, or `beeApiUrl` is not an `http:` or `https:` URL without credentials, query or fragment
- a plain `Error` if constructed where there is no `window` (a server render)

**Example:**

```typescript
const client = new SwarmIdClient({
  iframeOrigin: 'https://id.swarm.example.com',
  timeout: 60000,
  metadata: {
    name: 'My app',
    description: 'A decentralized application built on Swarm',
    icon: 'data:image/svg+xml;base64,...',
  },
  onConnectionChange: (info) => {
    updateUI(info)
  },
})
```

## Lifecycle Methods

### `initialize()`

Initializes the client by creating and embedding the proxy iframe.

This method must be called before using any other client methods. It creates a hidden iframe, waits for the proxy to initialize, identifies the parent application to the proxy, and waits for the proxy to signal readiness.

**Returns:** `Promise<void>` - Resolves when the client is fully initialized

**Throws:**

- `invalid-state` if the client is already initialized, or `destroy()` runs before it resolves
- `init-failed` if the iframe fails to load, the proxy refuses the page's origin (it serves only the sites on its allow list, and the error message says which site and why), or the proxy does not respond within the initialization timeout period (configurable via `initializationTimeout`, defaults to 30 seconds)

**Example:**

```typescript
const client = new SwarmIdClient({ ... })
try {
  await client.initialize()
  console.log('Client ready')
} catch (error) {
  console.error('Failed to initialize:', error)
}
```

---

### `destroy()`

Destroys the client and releases all resources.

This method should be called when the client is no longer needed. It performs the following cleanup:

- Rejects every pending request, and a pending `initialize()`, with a `SwarmIdError` of code `invalid-state`
- Removes the message event listener
- Removes the iframe, and every button `mountButton()` showed, from the DOM
- Resets the client to an uninitialized state

After calling `destroy()`, the client instance cannot be reused. Create a new instance if you need to reconnect.

**Returns:** `void`

**Example:**

```typescript
// Clean up when component unmounts
useEffect(() => {
  const client = new SwarmIdClient({ ... })
  client.initialize()

  return () => {
    client.destroy()
  }
}, [])
```

## Authentication Methods

### `mountButton(container, options)`

Shows a Swarm ID button in `container`. The button is a small frame of Swarm ID's own, apart from the hidden frame `initialize()` creates, and it fills the container, so give the container the size the button should have.

A click on it opens the connect window, and the window hands the session back to your site's Swarm ID frame. `onConnectionChange` fires as for any sign-in. This is how a person signs in, or changes the stamp your site uses, whenever your site and Swarm ID are on different sites, for example your site at its own domain and Swarm ID at `solarpunkid.bzz.link`. There the browser keeps Swarm ID's frames apart from Swarm ID's own storage, and a frame may open a window only from a click inside it, so the click has to happen in a Swarm ID frame. It works the same where the two share storage.

Unmounting removes only the button, at any time: the session stays, and signing out stays [`disconnect()`](#disconnect). So a site can show the button in a panel and close the panel while the window is open or once the person is signed in. The sign-in and the stamp the person confirms in the window still reach your site, as long as your page is not reloaded or left before they confirm. A button unmounted while its window is open stays hidden until the window closes, because the window reads from it, as it opens, where to hand the session. Unmounting it, or removing its container, in the moment between the click and the window opening loses that sign-in. Once unmounted, `update()` does nothing and `onWindowChange` is not called again.

**Parameters:**

| Parameter                | Type                                 | Required | Description                                                                                                        |
| ------------------------ | ------------------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------ |
| `container`              | `HTMLElement`                        | Yes      | The element the button fills                                                                                       |
| `options.action`         | `"sign-in" \| "change-stamp"`        | Yes      | `sign-in` for a person signed out, `change-stamp` for one signed in. Decides the default label                     |
| `options.config`         | `ButtonConfig`                       | No       | The label, its busy and disabled states, colours and typography, see [Button look](#button-look)                   |
| `options.onWindowChange` | `(state: ButtonWindowState) => void` | No       | Called with `open` and `closed` for the button's connect window, and `blocked` when the browser refused to open it |

**Returns:** `MountedButton`

| Member                       | Description                                                                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ready`                      | A promise that resolves once the button is shown, and rejects with `init-failed` when Swarm ID refuses your site or does not answer within `initializationTimeout` |
| `update({ action, config })` | Changes what the button does or how it looks, in place                                                                                                             |
| `unmount()`                  | Removes the button and leaves the session as it is                                                                                                                 |

**Throws:**

- `invalid-state` if the client is not initialized
- `invalid-request` if `action` or a `config` value is not one the button takes, a plain-http font file for example. The message names the field, and `update()` refuses such a value the same way

**Example:**

```typescript
await client.initialize()

const button = client.mountButton(document.getElementById('sign-in')!, {
  action: client.connectionInfo.identity ? 'change-stamp' : 'sign-in',
  config: { text: 'Sign in', backgroundColor: '#000', borderRadius: '6px' },
  onWindowChange: (state) => {
    if (state === 'blocked') showHint('Allow pop-ups for this site to sign in')
  },
})
await button.ready

// The person signed in: offer the stamp change instead
button.update({ action: 'change-stamp', config: { text: 'Change stamp' } })

// Closing the panel the button sits in
button.unmount()
```

`destroy()` unmounts every button the client mounted.

### Button look

The button is painted inside Swarm ID's frame, where your page's CSS cannot reach it, so everything it should match is said in `ButtonConfig`. It fills its frame, and a label that does not fit ends in an ellipsis. It is a native button, reached with Tab and pressed with Enter or Space, and its accessible name is its label, or `ariaLabel` when you give one.

```typescript
interface ButtonConfig {
  text?: string
  busyText?: string
  ariaLabel?: string
  disabled?: boolean
  busy?: boolean
  backgroundColor?: string
  color?: string
  borderRadius?: string
  borderColor?: string
  borderWidth?: string
  borderStyle?: 'solid' | 'dashed' | 'dotted' | 'double'
  fontFamily?: string
  fontSize?: string
  fontWeight?: string | number
  fontFaces?: {
    family: string
    url: string
    weight?: string | number
    style?: 'normal' | 'italic' | 'oblique'
  }[]
}
```

| Property          | Type                                          | Description                                                                                                       | Default                                                |
| ----------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `text`            | `string`                                      | The label                                                                                                         | "Sign in with Swarm ID", or "Change stamp in Swarm ID" |
| `busyText`        | `string`                                      | The label while the connect window is open, or while `busy` is set                                                | "Waiting for Swarm ID"                                 |
| `ariaLabel`       | `string`                                      | The accessible name, where the label alone does not say what the button does                                      | the label                                              |
| `disabled`        | `boolean`                                     | Shown but not clickable, and out of the tab order                                                                 | `false`                                                |
| `busy`            | `boolean`                                     | Shown as working and not clickable, for a step of your own such as signing out. Stays focusable                   | `false`                                                |
| `backgroundColor` | `string`                                      | CSS colour                                                                                                        | `#dd7200`                                              |
| `color`           | `string`                                      | CSS colour of the label                                                                                           | `white`                                                |
| `borderRadius`    | `string`                                      | CSS border-radius of the button and its frame                                                                     | `0`                                                    |
| `borderColor`     | `string`                                      | CSS colour of a border, for a secondary style. Naming it or `borderWidth` draws one, kept while busy and disabled | the label's colour                                     |
| `borderWidth`     | `string`                                      | CSS width of the border                                                                                           | `1px` once a border is drawn                           |
| `borderStyle`     | `'solid' \| 'dashed' \| 'dotted' \| 'double'` | Style of the border                                                                                               | `solid`                                                |
| `fontFamily`      | `string`                                      | CSS font-family. A stack resolves against Swarm ID's frame, so name web-safe or system families                   | the frame's own font                                   |
| `fontSize`        | `string`                                      | CSS font-size                                                                                                     | `14px`                                                 |
| `fontWeight`      | `string \| number`                            | CSS font-weight                                                                                                   | `600`                                                  |
| `fontFaces`       | `ButtonFontFace[]`                            | Up to 8 font files the button frame loads for the label, see below                                                | none                                                   |

The button is busy by itself while its connect window is open, and comes back when the window closes.

To paint the label in a font your site serves, name the file in `fontFaces` and the family first in `fontFamily`:

```typescript
client.mountButton(container, {
  action: 'sign-in',
  config: {
    fontFamily: "'Brand Sans', system-ui, sans-serif",
    fontFaces: [
      { family: 'Brand Sans', url: 'https://my-app.example/fonts/brand-sans.woff2', weight: 600 },
    ],
  },
})
```

The frame fetches the file itself, from Swarm ID's origin, so serve it with an `Access-Control-Allow-Origin` header that names Swarm ID's origin (`https://solarpunkid.bzz.link`) or `*`. Only https URLs are taken, and http on `localhost` in a development build of Swarm ID. A file that does not load leaves the label in the next family of `fontFamily`, and the frame says so once in its console.

### Signing in from your own control

Where your site and Swarm ID share the browser's storage, a site on the same site as Swarm ID such as a self-hosted copy on your own domain, [`connect()`](#connectoptions) opens the connect window from your page instead, from your own button. Anywhere else it refuses with `button-required`, because a window your page opens could never hand the session over, and would end on "Connected" with your site still signed out. The Swarm ID button works in both cases, so a site that always mounts it never needs `connect()`.

```typescript
try {
  await client.connect()
} catch (error) {
  if (error instanceof SwarmIdError && error.code === 'button-required') {
    client.mountButton(container, { action: 'sign-in' })
  }
}
```

**Authentication Flow:**

1. The person clicks the Swarm ID button, or your own control calls `client.connect()` where storage is shared
2. The connect window opens with the app metadata
3. The person authenticates with their Swarm ID
4. The window hands the session to your site's Swarm ID frame, through the shared storage or directly
5. `onConnectionChange` fires with the new connection snapshot

### `checkAuthStatus()`

Checks the current authentication status with the Swarm ID proxy.

**Returns:** `Promise<AuthStatus>` - The authentication status object

| Property        | Type                  | Description                                                                          |
| --------------- | --------------------- | ------------------------------------------------------------------------------------ |
| `authenticated` | `boolean`             | Whether the user is currently authenticated                                          |
| `origin`        | `string \| undefined` | The origin that authenticated (if authenticated)                                     |
| `beeApiUrl`     | `string \| undefined` | The Bee node this site gave, if it gave one. The person's own node is never reported |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the request times out

**Example:**

```typescript
const status = await client.checkAuthStatus()
if (status.authenticated) {
  console.log('Authenticated from:', status.origin)
}
```

### `connect(options?)`

Opens the Swarm ID connect window from your page, where your site's Swarm ID frame shares Swarm ID's storage. The window writes the connection to that storage and the frame picks it up. Anywhere else this refuses with `button-required` and opens nothing: use [`mountButton()`](#mountbuttoncontainer-options), see [Signing in from your own control](#signing-in-from-your-own-control).

It works the same while the person is already signed in. The window then lists their account as used with your site and asks again which stamp your site uses, starting on the current one. Every connect signs your site in with no stamp, first or not, and the stamp arrives when the person confirms in the window, see [The stamp your site uses](#the-stamp-your-site-uses).

**Parameters:**

| Parameter           | Type                  | Required | Description                                                                    |
| ------------------- | --------------------- | -------- | ------------------------------------------------------------------------------ |
| `options`           | `ConnectOptions`      | No       | Configuration options for the authentication window                            |
| `options.popupMode` | `"window" \| "popup"` | No       | Whether to open as a popup window ("popup") or full window ("window", default) |

**ConnectOptions Interface:**

```typescript
interface ConnectOptions {
  popupMode?: 'popup' | 'window' // Default: "window"
}
```

**Returns:** `Promise<void>` - Resolves when the authentication popup has been opened

**Throws:**

- `invalid-state` if the client is not initialized
- `button-required` if your site's Swarm ID frame does not share Swarm ID's storage, or it is not proven that it does
- `popup-blocked` if the browser blocks the popup

**Example:**

```typescript
const client = new SwarmIdClient({ ... })
await client.initialize()

// Open authentication page (default: new window)
await client.connect()

// Open as popup window
await client.connect({ popupMode: 'popup' })
```

### `disconnect()`

Disconnects the current session and clears authentication data.

After disconnection, the user will need to re-authenticate to perform uploads or access identity-related features. The `onConnectionChange` callback will fire with an un-authenticated snapshot (no `identity`, `canUpload: false`, `uploadMode: "unavailable"`). Note that `canUpload` is reported as `false` even when a subsidised gateway is configured, because uploads still require an authenticated app secret.

**Returns:** `Promise<void>` - Resolves when disconnection is complete

**Throws:**

- `invalid-state` if the client is not initialized
- `internal` if the proxy reports the disconnect failed
- `timeout` if the request times out

**Example:**

```typescript
await client.disconnect()
console.log('User logged out')
```

### `deriveAppSecret(label)`

Derive 32 bytes of app material from this app's secret and a label of the app's choosing. The same account, app and label give the same bytes on every device, and nobody without the account can guess them. Use it to seed a feed topic or other app material without exposing the app's public key.

**Parameters:**

| Parameter | Type     | Description                                             |
| --------- | -------- | ------------------------------------------------------- |
| `label`   | `string` | Domain separator chosen by the app, e.g. `"state-feed"` |

**Returns:** `Promise<Uint8Array>` — the derived 32 bytes

**Throws:** `Error` if the client is not initialized or not authenticated

```typescript
const seed = await client.deriveAppSecret('state-feed')
const topic = keccak256(seed) // a stable feed topic nobody else can compute
```

### `getChatKey()`

The site's chat key: the secp256k1 private key your chat signs its messages with. Its address is the chat address that [`chatBinding`](#connectioninfo-property) names, so a reader who recovers a message's author can check it against the binding with `acceptedChatBinding`. The iframe derives it from the app secret, which never leaves the iframe, and the same account and site give the same key on every device. The library keeps it in memory only and never stores it. Hold it no longer than your chat needs it, and never publish it.

**Returns:** `Promise<Uint8Array>`, the 32-byte private key

**Throws:** `SwarmIdError` if the client is not initialized, or with code `not-authenticated` when no account is connected

```typescript
const chatKey = await client.getChatKey()
const signer = new PrivateKey(chatKey) // signer.publicKey().address() is the binding's chat address
```

### `connectionInfo` (property)

Synchronous accessor for the current connection state. Populated by the proxy as soon as it is ready and refreshed automatically whenever any of the derived fields change (identity rename, default-stamp change, the person giving your site another stamp, account migration, postage stamp purchased, auth transitions). Subscribe to `onConnectionChange` to react to updates.

**Type:** `ConnectionInfo`

**Throws:** `invalid-state` if `initialize()` has not resolved yet.

| Property                        | Type                                                                                                            | Description                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canUpload`                     | `boolean`                                                                                                       | Whether the user can upload data                                                                                                                                                                                                                                                                                                                                  |
| `uploadMode`                    | `"user-stamp" \| "subsidised" \| "unavailable"`                                                                 | How uploads will be handled. See [Upload Availability](../subsidised-gateway/#upload-availability-truth-table)                                                                                                                                                                                                                                                    |
| `uploadUnavailableReason`       | `"no-stamp" \| "stamper-failed" \| "stamp-expired" \| "stamp-not-usable" \| "session-unconfirmed" \| undefined` | Why `uploadMode` is `"unavailable"`; absent whenever uploads work. See [Why Uploads Are Unavailable](../subsidised-gateway/#why-uploads-are-unavailable)                                                                                                                                                                                                          |
| `storagePartitioned`            | `boolean \| undefined`                                                                                          | `true` when the browser gave the proxy iframe its own partitioned store (Safari ITP, strict privacy settings). Reported for UI messaging; it does **not** decide whether you can upload                                                                                                                                                                           |
| `identity`                      | `object \| undefined`                                                                                           | The connected identity details (if authenticated)                                                                                                                                                                                                                                                                                                                 |
| `identity.id`                   | `string`                                                                                                        | Unique identifier for the identity                                                                                                                                                                                                                                                                                                                                |
| `identity.name`                 | `string`                                                                                                        | Display name of the identity                                                                                                                                                                                                                                                                                                                                      |
| `identity.address`              | `string`                                                                                                        | Ethereum address associated with the identity                                                                                                                                                                                                                                                                                                                     |
| `identity.publicKey`            | `string \| undefined`                                                                                           | Public key of the identity                                                                                                                                                                                                                                                                                                                                        |
| `identity.sharingPublicKey`     | `string \| undefined`                                                                                           | The account-wide ACT key: grant to it to share with this person in every app they use. See [Which key do I grant to?](#which-key-do-i-grant-to)                                                                                                                                                                                                                   |
| `identity.postageSignerAddress` | `string \| undefined`                                                                                           | The address the account's postage signer stamps with, bare hex like `address`. An app that funds storage for the account buys a batch with it as `createBatch`'s owner; the account then adopts the batch in the identity site (Storage, Add drive, Use existing batch) with its own key. Knowing the address lets an app buy for the account, never spend for it |
| `identity.avatar`               | `Avatar`                                                                                                        | Ready-to-render account avatar. See [Avatars](#avatars)                                                                                                                                                                                                                                                                                                           |
| `appKey`                        | `object \| undefined`                                                                                           | The app-specific key details                                                                                                                                                                                                                                                                                                                                      |
| `appKey.address`                | `string`                                                                                                        | Ethereum address of the app key                                                                                                                                                                                                                                                                                                                                   |
| `appKey.publicKey`              | `string`                                                                                                        | Public key of the app key                                                                                                                                                                                                                                                                                                                                         |
| `beeApiUrl`                     | `string \| undefined`                                                                                           | The Bee node this site gave with `beeApiUrl` or `setBeeApiUrl()`, which its content goes through. Absent when it gave none: the person's own node is never reported. In subsidised mode the gateway is used instead                                                                                                                                               |
| `postageBatchId`                | `string \| undefined`                                                                                           | The batch id of the stamp the person gave your site in Swarm ID, the one `getPostageBatch()` reads and `stampChunk()` stamps with. Absent when your site has none. The person can change it in the connect window, or on the Apps screen once your site's drive is confirmed, see [The stamp your site uses](#the-stamp-your-site-uses)                           |
| `chatBinding`                   | `{ message: string, signature: string } \| undefined`                                                           | The account's signed statement that the address of this site's chat key is its chat address on this site. Publish it beside your chat so readers can check it with `verifyChatBinding`, and trust the newest one per site. Present only on a session the connect window handed over. See `docs/Chat-Binding.md` in the repository                                 |

`chatBinding` is often absent, and a site must work without it. It is there only when the connect window handed the session over, which happens when the browser keeps this frame's storage apart from the identity site's. A session read out of shared storage, where your site and the identity site are the same site, carries none. Neither does a connection made before bindings existed, or one whose kept binding names an address other than the site's chat key, until the person next unlocks their account in the connect window for your site. A reconnect that would skip the unlock is taken only when the kept binding still names the chat key, so the window asks for the unlock and signs a fresh one otherwise. Treat a missing binding as "this chat address is not linked to an account", never as an error, and listen on `onConnectionChange` for one that arrives later.

**Example:**

```typescript
const info = client.connectionInfo
if (info.canUpload) {
  if (info.uploadMode === 'subsidised') {
    console.log('Uploads will use the subsidised gateway')
  } else {
    console.log('Uploads will use your postage stamp')
  }
} else if (info.uploadUnavailableReason === 'no-stamp') {
  console.log('This site has no drive: connect again and confirm one in Swarm ID to upload')
} else if (info.uploadUnavailableReason === 'stamper-failed') {
  console.log('A drive is attached, but the write path did not build')
} else {
  console.log('Not connected yet')
}
```

### `getPostageBatch()`

Gets the current postage batch for the authenticated identity.

Returns information about the postage stamp your site uses, including batch ID, utilization, depth, and TTL. Each call reads the stamp the site uses at that moment, so after `connectionInfo.postageBatchId` changes the next call describes the new one.

**Returns:** `Promise<PostageBatch | undefined>` - The postage batch info, or `undefined` if none is configured

| Property        | Type                  | Description                                                                                                                                                                                                      |
| --------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `batchID`       | `string`              | The batch ID (64 hex characters)                                                                                                                                                                                 |
| `utilization`   | `number`              | Bee's fill count of the fullest bucket, **not** a percentage. Usage is `utilization / 2^(depth - bucketDepth)`; a batch stops accepting uploads when one bucket fills, before the nominal `2^depth × 4096` bytes |
| `usable`        | `boolean`             | Whether the batch is usable                                                                                                                                                                                      |
| `label`         | `string`              | Human-readable label                                                                                                                                                                                             |
| `depth`         | `number`              | Batch depth                                                                                                                                                                                                      |
| `amount`        | `string`              | Batch amount                                                                                                                                                                                                     |
| `bucketDepth`   | `number`              | Bucket depth                                                                                                                                                                                                     |
| `blockNumber`   | `number`              | Block number when created                                                                                                                                                                                        |
| `immutableFlag` | `boolean`             | Whether the batch is immutable                                                                                                                                                                                   |
| `exists`        | `boolean`             | Whether the batch exists                                                                                                                                                                                         |
| `batchTTL`      | `number \| undefined` | Time-to-live in seconds                                                                                                                                                                                          |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the request times out

**Example:**

```typescript
const batch = await client.getPostageBatch()
if (batch) {
  console.log('Batch ID:', batch.batchID)
  console.log('Utilization:', batch.utilization)
  console.log('Depth:', batch.depth)
  console.log('TTL:', batch.batchTTL)
} else {
  console.log('No postage batch configured')
}
```

## Bee Connectivity Methods

### The site's own Bee node

By default the iframe talks to the Bee node the person set in Swarm ID's network
settings, or the public gateway when they set none. A site that has its own source, such as a node
its viewer picked, names it with the `beeApiUrl` constructor option, and changes it at runtime with
`setBeeApiUrl()`. In that site's iframe the site's node then carries the site's own content.

**Follows the site's node:**

- the reads the site asks for: chunks, bytes, files, single-owner chunks, feeds, GSOC and ACT
- the stamped uploads the site asks for, made with the person's drive
- the Bee reads behind `getPostageBatch()`, `isBeeConnected()` and `getNodeInfo()`

**Never follows it, and stays on the person's own node:**

- the check, after a reload, that the person has not ended or removed this site's session
- the device roster and the device-state publishes that keep the person's devices in step
- the write lock, lease and state chunks that share the person's drive between their devices

Those decide what this session may do with the person's account and drive, so a site must not be
able to answer them from a node of its own.

- **Only that site.** The address is held by the one iframe the site embeds. Every other site, and
  Swarm ID's own pages, keep the person's setting, and the person's setting itself is never
  changed.
- **Never stored.** Nothing writes the address to storage, the account or a device sync feed. The
  site passes it again on every load.
- **The node must allow the identity site's origin** in its CORS configuration, as any node used
  through the iframe must. See [Using Your Own Bee Node](../own-bee-node/).
- **A subsidised gateway is kept beside it.** A person's own custom node switches a site's
  subsidised gateway off. A node the site names does not, since the site asked for both, and in
  subsidised mode uploads and reads go to the gateway as before. See
  [Subsidised Gateway](../subsidised-gateway/#understanding-the-table).
- `connectionInfo.beeApiUrl` and `checkAuthStatus().beeApiUrl` give back the address the site
  gave, and nothing when it gave none. The person's own node is never reported to a site.

The address is an `http:` or `https:` URL, optionally with a path, the way a gateway in front of Bee
is often mounted. Credentials, a query and a fragment are refused.

### `setBeeApiUrl(url)`

Changes the Bee node this site's content goes through, without a reload. It replaces the
`beeApiUrl` given at construction, and takes over from the person's own setting if none was given.
Works whether or not anyone is signed in. See [The site's own Bee node](#the-sites-own-bee-node).

**Parameters:**

| Parameter | Type     | Description                                                                                |
| --------- | -------- | ------------------------------------------------------------------------------------------ |
| `url`     | `string` | An `http:` or `https:` URL, optionally with a path, without credentials, query or fragment |

**Returns:** `Promise<void>`, resolved once the iframe uses the new node. `connectionInfo.beeApiUrl`
follows through `onConnectionChange`.

**Throws:**

- `invalid-request` if `url` is not such a URL, and nothing is sent
- `invalid-state` if the client is not initialized
- `timeout` if the request times out

**Example:**

```typescript
await client.setBeeApiUrl('https://bee.example.com/')
console.log(client.connectionInfo.beeApiUrl) // https://bee.example.com/
```

### `isBeeConnected()`

Checks whether the Bee node is reachable.

This method never throws an exception. If the client is not initialized, the request times out, or any other error occurs, it returns `false`.

**Returns:** `Promise<boolean>` - `true` if the Bee node is reachable, `false` otherwise

**Example:**

```typescript
const connected = await client.isBeeConnected()
if (connected) {
  console.log('Bee node is online')
} else {
  console.log('Bee node is offline')
}
```

### `getNodeInfo()`

Gets information about the Bee node configuration. Needs a real Bee node: the [public gateway](../public-gateway/) has no `/node` endpoint and this call fails there. Do not gate uploads on it; its purpose is to detect a dev-mode node, where deferred uploads are required. Nothing else tells you: a direct upload against a dev-mode node does not fail with a mode error, it waits out the request timeout and rejects with `Request timeout after 30000ms`.

This method retrieves the current Bee node's operating mode and feature flags. Use this to determine if deferred uploads are required (dev mode) or if direct uploads are available (production modes).

**Returns:** `Promise<{ beeMode, chequebookEnabled, swapEnabled }>` — an inline object; there is no exported `NodeInfo` type

| Property            | Type      | Description                                                         |
| ------------------- | --------- | ------------------------------------------------------------------- |
| `beeMode`           | `string`  | The Bee node operating mode ("dev", "light", "full", "ultra-light") |
| `chequebookEnabled` | `boolean` | Whether the chequebook is enabled                                   |
| `swapEnabled`       | `boolean` | Whether SWAP is enabled                                             |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the Bee node is not reachable
- `Error` if the request times out

**Example:**

```typescript
const nodeInfo = await client.getNodeInfo()
if (nodeInfo.beeMode === 'dev') {
  // Dev mode requires deferred uploads
  await client.uploadData(data, { deferred: true })
} else {
  // Production modes can use direct uploads
  await client.uploadData(data, { deferred: false })
}
```

## Data Methods

### `uploadData(data, options?, requestOptions?)`

Uploads raw binary data to the Swarm network. The reference it returns is read back with [`downloadData`](#downloaddatareference-options-requestoptions), or from a gateway at `/bytes/<reference>`; it carries no manifest, so `downloadFile` and `/bzz/` cannot resolve it.

The data is uploaded using the authenticated user's postage stamp. Progress can be tracked via the `options.onProgress` callback.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data`                          | `Uint8Array`             | Yes      | The binary data to upload                                                                                                                                                                                                                                                                |
| `options`                       | `UploadOptions`          | No       | Upload configuration                                                                                                                                                                                                                                                                     |
| `options.pin`                   | `boolean`                | No       | Whether to pin the data locally (defaults to `false`; ignored on a subsidised gateway)                                                                                                                                                                                                   |
| `options.encrypt`               | `boolean`                | No       | Whether to encrypt the data (defaults to `false`). The 128-hex reference then contains the decryption key: a capability, not an address — see [Quick Start](../getting-started/#upload-and-download-bytes)                                                                               |
| `options.tag`                   | `number`                 | No       | Tag ID for tracking upload progress (ignored on a subsidised gateway)                                                                                                                                                                                                                    |
| `options.deferred`              | `boolean`                | No       | Whether to use deferred upload (defaults to `false`). A Bee node in dev mode serves only deferred uploads, and a direct upload against one fails as a request timeout, not as a mode error — see [`getNodeInfo`](#getnodeinfo). Not needed on the public gateway                         |
| `options.onProgress`            | `(progress) => void`     | No       | Callback for tracking upload progress                                                                                                                                                                                                                                                    |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                                                                                                                                                                    |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole upload — the round trip through the iframe as well as the Bee request; a file of a few MB over a testnet or the public gateway needs more, here or in `new SwarmIdClient({ timeout })` |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                                                                                                                                                                           |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                                                                                                                                                                               |

**Returns:** `Promise<UploadResult>`

| Property    | Type                  | Description                                     |
| ----------- | --------------------- | ----------------------------------------------- |
| `reference` | `string`              | The Swarm reference (hash) of the uploaded data |
| `tagUid`    | `number \| undefined` | The tag UID if a tag was created                |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated or cannot upload
- `Error` if the request times out

**Example:**

```typescript
const data = new TextEncoder().encode('Hello, Swarm!')
const result = await client.uploadData(data, {
  encrypt: true,
  onProgress: (progress) => {
    console.log(`Progress: ${progress.processed}/${progress.total}`)
  },
})
console.log('Reference:', result.reference)
```

### `downloadData(reference, options?, requestOptions?)`

Downloads raw binary data from the Swarm network: the counterpart of [`uploadData`](#uploaddatadata-options-requestoptions). Pass an encrypted (128-hex) reference here rather than putting it in a gateway URL, since the reference contains the decryption key.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                            |
| ------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `reference`                     | `string`                 | Yes      | The Swarm reference (64 or 128 hex chars)                                                                                              |
| `options`                       | `DownloadOptions`        | No       | Download configuration                                                                                                                 |
| `options.redundancyStrategy`    | `0-3`                    | No       | Strategy for handling redundancy                                                                                                       |
| `options.fallback`              | `boolean`                | No       | Whether to use fallback retrieval                                                                                                      |
| `options.timeoutMs`             | `number`                 | No       | Download timeout in milliseconds, carried in the download options. Not the call's bound — that is `requestOptions.timeout` below       |
| `options.actPublisher`          | `Uint8Array \| string`   | No       | ACT publisher for encrypted content                                                                                                    |
| `options.actHistoryAddress`     | `Uint8Array \| string`   | No       | ACT history address for encrypted content                                                                                              |
| `options.actTimestamp`          | `number \| string`       | No       | ACT timestamp for encrypted content                                                                                                    |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                  |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole round trip, not only the Bee request |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                         |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                             |

**Returns:** `Promise<Uint8Array>` - The downloaded data

**Throws:**

- `Error` if the client is not initialized
- `Error` if the reference is not found
- `Error` if the request times out

**Example:**

```typescript

```

## File Methods

### `uploadFile(file, name?, options?, requestOptions?)`

Uploads a file to the Swarm network, wrapped in a manifest that carries its name and content type. The reference is read back with [`downloadFile`](#downloadfilereference-path-options-requestoptions). A gateway's `/bzz/<reference>/` is only for a plain reference, uploaded with `encrypt: false`: the default one carries the key, which [never goes in a gateway URL](../public-gateway/#what-that-means-for-an-app).

Accepts either a File object (from file input) or raw Uint8Array data. When using a File object, the filename is automatically extracted unless explicitly overridden.

Content and manifest are encrypted by default, so the reference is 128 hex characters and carries the key — the same rule as [`uploadFiles`](#uploadfilesfiles-options-requestoptions). `encryptManifest: false` gives a 64-character reference whose manifest anyone can read over encrypted content; `encrypt: false` leaves everything plain, which is what a `/bzz/` gateway link to a public file wants.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `file`                          | `File \| Uint8Array`     | Yes      | The file to upload                                                                                                                                                                                                                                                                       |
| `name`                          | `string`                 | No       | Filename (extracted from File object if not provided)                                                                                                                                                                                                                                    |
| `options`                       | `UploadOptions`          | No       | Upload configuration (see `uploadData`)                                                                                                                                                                                                                                                  |
| `options.encrypt`               | `boolean`                | No       | Encrypt the file content (defaults to `true`). `false` also leaves the manifest plain                                                                                                                                                                                                    |
| `options.encryptManifest`       | `boolean`                | No       | Encrypt the manifest too, so the reference carries the key (defaults to `true`)                                                                                                                                                                                                          |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                                                                                                                                                                    |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole upload — the round trip through the iframe as well as the Bee request; a file of a few MB over a testnet or the public gateway needs more, here or in `new SwarmIdClient({ timeout })` |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                                                                                                                                                                           |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                                                                                                                                                                               |

**Returns:** `Promise<UploadResult>` - Contains `reference` and optional `tagUid`

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated or cannot upload
- `Error` if the request times out

**Example:**

```typescript
// From file input
const fileInput = document.querySelector('input[type="file"]')
const file = fileInput.files[0]
const result = await client.uploadFile(file)

// From Uint8Array with custom name
const data = new Uint8Array([...])
const result = await client.uploadFile(data, 'document.pdf')
```

### `downloadFile(reference, path?, options?, requestOptions?)`

Downloads a file from the Swarm network: the counterpart of [`uploadFile`](#uploadfilefile-name-options-requestoptions). It resolves a manifest, so a reference from `uploadData` fails here inside the manifest parser; use `downloadData` for those.

Returns both the file data and its original filename (if available). For manifest references, an optional path can be specified to retrieve a specific file from the manifest.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                            |
| ------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `reference`                     | `string`                 | Yes      | The Swarm reference of the file                                                                                                        |
| `path`                          | `string`                 | No       | Path within a manifest to retrieve a specific file                                                                                     |
| `options`                       | `DownloadOptions`        | No       | Download configuration (see `downloadData`)                                                                                            |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                  |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole round trip, not only the Bee request |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                         |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                             |

**Returns:** `Promise<FileData>`

| Property | Type         | Description       |
| -------- | ------------ | ----------------- |
| `name`   | `string`     | The filename      |
| `data`   | `Uint8Array` | The file contents |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the reference is not found
- `Error` if the request times out

**Example:**

```typescript
const file = await client.downloadFile('a1b2c3...')
console.log('Filename:', file.name)

// Create download link
const blob = new Blob([file.data])
const url = URL.createObjectURL(blob)
```

### `uploadFiles(files, options?, requestOptions?)`

Uploads a folder as one manifest: a fork per file with its path and content type. A gateway serves a plain folder, uploaded with `encrypt: false`, at `/bzz/<reference>/<path>`; the default reference carries the key and stays out of gateway URLs. Takes what bee-js takes — the `FileList` of an `<input type="file" webkitdirectory>` or a dropped directory, a `File[]`, or `{ path, file }` pairs for a folder the app assembled itself. A `File`'s path is its `webkitRelativePath` with the picked folder's own name removed, or its name. Which files to include is the app's decision; the library uploads what it is given.

Read a folder back with [`listFiles`](#listfilesreference-requestoptions) and [`downloadData`](#downloaddatareference-options-requestoptions) per entry, or one file with [`downloadFile`](#downloadfilereference-path-options-requestoptions) and its path.

Every file is read into memory before the upload starts. For folders larger than that, upload the files with `uploadData` and build the manifest with `@ethersphere/core-sdk`'s `MantarayNode`.

**Parameters:**

| Parameter                 | Type                                                 | Required | Description                                                                                                                                                                                    |
| ------------------------- | ---------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `files`                   | `FileList \| Iterable<File \| { path, file: Blob }>` | Yes      | The folder's files                                                                                                                                                                             |
| `options`                 | `UploadFilesOptions`                                 | No       | Upload configuration                                                                                                                                                                           |
| `options.encrypt`         | `boolean`                                            | No       | Encrypt the file content (defaults to `true`). `false` also leaves the manifest plain                                                                                                          |
| `options.encryptManifest` | `boolean`                                            | No       | Encrypt the manifest too, so the root reference carries the key (defaults to `true`). `false` gives a 32-byte root reference whose manifest anyone can read, while the content stays encrypted |
| `options.indexDocument`   | `string`                                             | No       | The file the bare `/bzz/<reference>/` serves (`website-index-document`), e.g. `index.html`                                                                                                     |
| `options.errorDocument`   | `string`                                             | No       | The file served for a path that is not in the folder (`website-error-document`)                                                                                                                |
| `options.pin`             | `boolean`                                            | No       | Pin on the user's own node (defaults to `false`; ignored on a subsidised gateway)                                                                                                              |
| `options.deferred`        | `boolean`                                            | No       | Whether to use deferred upload (defaults to `false`); see [`uploadData`](#uploaddatadata-options-requestoptions)                                                                               |
| `options.tag`             | `number`                                             | No       | Tag ID for tracking upload progress                                                                                                                                                            |
| `options.onProgress`      | `(progress) => void`                                 | No       | Called once per file with `{ total, processed }`                                                                                                                                               |
| `options.useWorkers`      | `boolean`                                            | No       | Stamp in a worker pool, as [`uploadData`](#uploaddatadata-options-requestoptions) does                                                                                                         |
| `options.workerCount`     | `number`                                             | No       | Size of that pool                                                                                                                                                                              |
| `requestOptions`          | `RequestOptions`                                     | No       | Request configuration; `timeout` bounds the whole upload, see [`uploadFile`](#uploadfilefile-name-options-requestoptions)                                                                      |

**Returns:** `Promise<UploadResult>` - Contains `reference` (the manifest's) and optional `tagUid`

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated or cannot upload
- `Error` if the request times out

**Example:**

```typescript
// <input type="file" webkitdirectory>
const { reference } = await client.uploadFiles(input.files)

// a public website: plain, so a gateway serves it at /bzz/<reference>/
await client.uploadFiles(input.files, {
  encrypt: false,
  indexDocument: 'index.html',
})

// a folder the app assembled
await client.uploadFiles([
  { path: 'index.html', file: new Blob([html], { type: 'text/html' }) },
  { path: 'assets/app.js', file: new Blob([js], { type: 'text/javascript' }) },
])
```

## Chunk Methods

### `uploadChunk(data, options?, requestOptions?)`

Uploads a single chunk to the Swarm network.

Chunks are the fundamental unit of storage in Swarm (4KB each). This method is useful for low-level operations or when implementing custom chunking strategies.

`data` is the chunk's payload, not a finished chunk: the proxy builds the content-addressed chunk around it (span header, BMT address) and returns that address. A chunk that already carries its span header is wrapped a second time and stored under an address nothing else computes. To store a folder as a manifest, use [`uploadFiles`](#uploadfilesfiles-options-requestoptions); to save a Mantaray tree of your own, use `saveMantarayTreeRecursively` with [`uploadData`](#uploaddatadata-options-requestoptions), which hands back the reference each node was stored under.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                            |
| ------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `data`                          | `Uint8Array`             | Yes      | The chunk payload, 1 to 4096 bytes                                                                                                     |
| `options`                       | `UploadOptions`          | No       | Upload configuration (see `uploadData`)                                                                                                |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                  |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole round trip, not only the Bee request |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                         |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                             |

**Returns:** `Promise<UploadResult>` - Contains the `reference` of the uploaded chunk

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated or cannot upload
- `Error` if the request times out

**Example:**

```typescript
const chunk = new Uint8Array(4096) // 4KB chunk
chunk.fill(0x42) // Fill with data
const result = await client.uploadChunk(chunk)
console.log('Chunk reference:', result.reference)
```

### The stamp your site uses

Swarm ID gives each connected site one stamp (a "drive" in Swarm ID's own words): the account's default, another of the person's stamps, or none. The connect window asks which one every time the person connects to your site, starting on the one your site uses now. Your site never chooses among the person's stamps and cannot preselect one, it only reads the one it was given.

- Every connect, a first one or a reconnect, signs your site in with no stamp: `postageBatchId` is absent and `stampChunk()` is refused, as below. The stamp arrives when the person confirms the drive with "Go to app" in the window, whether or not your site and Swarm ID share the browser's storage. No reload is needed and no signaling server is involved. A frame whose storage the browser keeps apart, which is the usual case for a site on another domain, is handed the confirmed drive by the window directly. If the person closes the window without confirming, your site stays signed in with no stamp, a reload included, until they connect again. Their choice in Swarm ID is kept as it was.
- To let the person change the stamp from your site, mount a Swarm ID button with the `change-stamp` action while they are signed in ([`mountButton()`](#mountbuttoncontainer-options)). Your site has no stamp from then until the person confirms.
- The confirmed drive can reach a frame kept apart only while your page still holds its Swarm ID frames. Unmounting the button is fine. If your site reloads, navigates away or opens the window again before the person confirms, it has no stamp until it connects again. When the window can tell the frames are gone it says so before it closes. When the frame reloaded in place it cannot tell, and says nothing.
- While your site waits for the confirm, only "Go to app" in the window ends the wait. A drive the person picks for your site on Swarm ID's Apps screen in the meantime is saved, but your site still has no stamp: the window starts on that pick at the next connect, and the site uses it once the person confirms there.
- Once the wait has ended, the person can also change the choice on Swarm ID's Apps screen, to another of their stamps or to none. That change reaches your open site when your site and Swarm ID share the browser's storage, through that store. A frame whose storage the browser keeps apart, and a frame on another device, hear of it only over the [account bus](../account-bus/) relay, so only while a bus signaling server is configured and the frame is open. Otherwise the frame keeps the stamp it was handed, a reload included, until the person connects to your site again.
- When a change arrives, `connectionInfo.postageBatchId` changes and `onConnectionChange` fires, and the next `getPostageBatch()`, `stampChunk()` and stamped upload use the new stamp. A client from before `postageBatchId` existed still gets the `onConnectionChange` call, and `getPostageBatch()` there names the new stamp.
- When the person disconnects or removes your site in Swarm ID, the stamp chosen for it is forgotten, and the next connect starts on the account default. Your own `disconnect()` leaves the choice alone, since nothing your site sends decides its stamp.
- With no stamp, `postageBatchId` is absent and `stampChunk()` is refused. A site that names a [subsidised gateway](../subsidised-gateway/) keeps uploading through it (`uploadMode: "subsidised"`), and one that names none is told `uploadUnavailableReason: "no-stamp"`.
- The per-app limits and the remembered inbox slots of `stampChunk()` belong to the stamp. A new stamp starts its own count, and going back to an earlier stamp finds its count and slots as they were left. The chat inbox stamped again on a new stamp takes a new slot there, then keeps it.
- To send the person to the screen for your site, link to `https://solarpunkid.bzz.link/#apps/<site>`, with your origin passed through `encodeURIComponent`. It opens the Apps tab on your site, and says so when your site is not connected to the account the person is signed in with.

```typescript
const client = new SwarmIdClient({
  iframeOrigin: 'https://solarpunkid.bzz.link',
  metadata: { name: 'My App' },
  onConnectionChange: async (info) => {
```

### `stampChunk(chunk)`

Stamps a chunk with the account's own postage stamp and hands the stamp back, so the app sends the chunk itself, through whatever Swarm access it chose: a gateway, its own Bee node or a browser node. The person's stamp still pays, the app only carries the bytes.

The whole chunk goes in, never an address: the iframe computes the address itself, so a stamp is only ever issued for bytes it has seen. Two shapes are accepted:

- **A content chunk**: `{ kind: 'content', data }`, where `data` is the 8-byte little-endian span followed by the payload.
- **A single-owner chunk the iframe signs in the same call**: `{ kind: 'soc', identifier, data, signer }`. `signer: 'app'` signs with the app's own secret, the same key [`makeSOCWriter()`](#makesocwritersigner-requestoptions) uses by default. `signer: { privateKey }` signs with a key the app supplies, such as a chat's shared GSOC inbox key.

Anything else is refused with `invalid-request`: a chunk that also names an address, an owner or a signature, a pre-signed chunk, and a single-owner chunk whose owner would be one of the account's own keys (the backup signer that owns its lock, partition state, device state and roster chunks, its postage signer, its ACT sharing key, its derivation and encryption keys, and the account address).

The stamp goes through the same write path as an upload: the cross-tab write lock, the device's partition lease, and a fresh slot in the bucket. It is returned only once the bucket counter it spent is saved and, for an account shared between devices, published, which is the guarantee an upload's acknowledgement carries. When the iframe cannot save the counter, the call is refused with `internal` and no stamp is returned, because a counter that was never saved could hand the same slot out again after a reload. Two different chunks never get the same bucket slot, and the slots the account keeps for its own bookkeeping are never handed out. The account's own lock and counter chunks stay inside the iframe and go through its own node.

#### The same single-owner chunk again

A chat sends every message as a new version of one single-owner chunk, its inbox, whose address never changes. The account's stamp is mutable, and on a mutable stamp Bee replaces a chunk stamped at the same slot when the new stamp has a newer timestamp. So when an app asks to stamp a single-owner chunk this device already stamped for it on this stamp, the iframe stamps it again at the same slot with a newer timestamp instead of spending a new one. A chat then keeps one slot for its inbox however many messages it sends.

- Stamping again spends no slot, so it does not count against the app's count, its bucket share or the account's own half. It still counts against the app's rate, and it is refused once the app has spent its whole count of new slots on that stamp.
- The timestamp is the current time, or one millisecond past the last stamp at that slot when that is later, as when the device's clock went back or two stamps of the address land in the same millisecond, so the new stamp always wins. The iframe keeps the last timestamp in memory from the moment it stamps, so a second stamp of the address made before the first's slot is remembered still gets a newer one.
- The iframe remembers the slot per app origin and per stamp in its own storage, beside the app's limits, so a reload keeps it. It remembers a slot only once the counter that spent it is saved and published, so a call refused for an unsaved or unpublished counter leaves nothing behind, and the next stamp of that address takes a new slot. It remembers up to 256 addresses per app and stamp (`SOC_RESTAMP_SLOT_LIMIT` in `lib/src/proxy/soc-restamp-slots.ts`). Past that, a new address takes a new slot each time, as a content chunk does.
- Only a slot this device took in its current partition lane is reused. On another device, or once this device holds another lane, the same address takes a new slot.
- A content chunk always takes a new slot.

In [subsidised mode](../subsidised-gateway/) the gateway stamps every upload, so there is no stamp of the account's to return: the call is refused with `upload-unavailable` and reason `subsidised`.

#### Limits per app

The stamp is the person's, so an app may only use part of it. Each app origin has its own limits, counted by the iframe in its own storage, so reloading the app does not reset them. The count is kept per stamp: when the account moves to a new stamp, every app starts a new count.

| Limit              | Default                                                                    | Resets                                       | Reason when refused |
| ------------------ | -------------------------------------------------------------------------- | -------------------------------------------- | ------------------- |
| Count              | 10,000 new slots per app on one stamp                                      | Never on that stamp. A new stamp starts at 0 | `app-stamp-count`   |
| Rate               | 60 stamps per app per 60 seconds                                           | When the 60 seconds are over                 | `app-stamp-rate`    |
| Bucket share       | A third of a bucket's data lane per app, rounded down (2 of 7 at depth 20) | Never on that stamp                          | `app-bucket-share`  |
| Account's own half | Apps together use only the lower half of a bucket's data lane              | Never on that stamp                          | `app-slice-full`    |

The last row keeps the account's own uploads safe from apps. Every bucket of the stamp gives each device a lane of data slots. Apps and the account take slots from the same counter, so no slot is ever handed out twice. An app stamp is refused once the lane is half used, whoever used it, and the upper half is only ever spent by the account's own uploads. So however much apps stamp, the account keeps at least half of every bucket.

Each refusal is `upload-unavailable` with the reason in the table, and its message names the limit and its value. A refused call spends no slot and is not counted. `app-stamp-rate` passes with time, the others stay until the account moves to a new stamp. The defaults are constants: `APP_STAMP_COUNT_LIMIT`, `APP_STAMP_RATE_LIMIT`, `APP_STAMP_RATE_WINDOW_MS` and `APP_BUCKET_SHARE` in `lib/src/proxy/app-stamp-limits.ts`, and `ACCOUNT_RESERVED_LANE_SHARE` in `lib/src/utils/batch-utilization.ts`.

**Parameters:**

| Parameter          | Type                                            | Required | Description                                                     |
| ------------------ | ----------------------------------------------- | -------- | --------------------------------------------------------------- |
| `chunk.kind`       | `'content' \| 'soc'`                            | Yes      | Which of the two shapes                                         |
| `chunk.data`       | `Uint8Array`                                    | Yes      | Span plus payload, 8 to 4104 bytes                              |
| `chunk.identifier` | `Uint8Array \| string`                          | SOC only | The 32-byte SOC identifier                                      |
| `chunk.signer`     | `'app' \| { privateKey: Uint8Array \| string }` | SOC only | The app's own secret, or a 32-byte private key the app supplies |

**Returns:** `Promise<StampedChunk>`

| Field       | Type     | Description                                                                                                                           |
| ----------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `address`   | `string` | The chunk's address, as the iframe computed it                                                                                        |
| `stamp`     | `string` | The postage stamp as hex: batch id, index, timestamp and signature, 113 bytes. The value of Bee's `swarm-postage-stamp` upload header |
| `owner`     | `string` | Single-owner chunk only: the owner it was signed as                                                                                   |
| `signature` | `string` | Single-owner chunk only: the signature, for `/soc/<owner>/<identifier>?sig=`                                                          |

**Throws:**

- `SwarmIdError` `not-authenticated` if no session is connected, or a session restored from storage turns out to have been ended while no page was open
- `SwarmIdError` `upload-unavailable` if the account cannot stamp, with reason `subsidised` in subsidised mode
- `SwarmIdError` `upload-unavailable` with reason `session-unconfirmed` when a session restored from storage could not yet check that it was not ended. A stamp from a restored session waits for that check, as every write does
- `SwarmIdError` `upload-unavailable` with reason `app-stamp-count`, `app-stamp-rate`, `app-bucket-share` or `app-slice-full` when the app has reached one of its [limits](#limits-per-app)
- `SwarmIdError` `invalid-request` for a chunk of the wrong shape or an owner that is one of the account's keys
- `SwarmIdError` `partition-contended` or `lease-lost` as for an upload
- `SwarmIdError` `internal` when the bucket counter the stamp spent could not be saved, and no stamp is returned

**Example:**

```typescript
// A content chunk, sent to the app's own gateway
const { address, stamp } = await client.stampChunk({ kind: 'content', data })
await fetch(`${gatewayUrl}/chunks`, {
  method: 'POST',
  headers: { 'swarm-postage-stamp': stamp },
  body: data,
})

// A single-owner chunk signed with the chat's shared inbox key
const soc = await client.stampChunk({
  kind: 'soc',
  identifier,
  data,
  signer: { privateKey: inboxKey },
})
await fetch(`${gatewayUrl}/soc/${soc.owner}/${identifierHex}?sig=${soc.signature}`, {
  method: 'POST',
  headers: { 'swarm-postage-stamp': soc.stamp },
  body: data,
})
```

## ACT Methods

ACT (Access Control Tries) methods enable encrypted data sharing with specific grantees. Data is encrypted and only users with the appropriate public key can decrypt it.

#### Which key do I grant to?

A grantee is a compressed public key, and a SwarmID user has two of them:

- **`appKey.publicKey`** — that user in **one app origin**. It is derived from the origin, so a share made out to it cannot be read from another origin, not even a dev build of the same app.
- **`identity.sharingPublicKey`** — that user across **every app they connect**. Use it to share a drive or folder between two apps, or between your dev and production origins.

The proxy tries both of the reader's keys on download, so nothing changes on the reading side. Trust consequence: anything granted to a sharing key can be read by every app that user connects — the person granting chooses which key to grant to.

By default the ACT is published with the app key, and only that origin can add or revoke grantees afterwards. Pass `publisher: "identity"` to `actUploadData` to publish with the sharing key instead, so any of the user's apps can manage the grantee list.

### `actUploadData(data, grantees, options?, requestOptions?)`

Uploads encrypted data to the Swarm network with access control for specific grantees.

The data is encrypted using ACT (Access Control Tries) and can only be downloaded by users who have one of the grantee public keys.

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                            |
| ------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `data`                          | `Uint8Array`             | Yes      | The binary data to upload                                                                                                              |
| `grantees`                      | `string[]`               | Yes      | Array of compressed public keys (66 hex chars each)                                                                                    |
| `options`                       | `ActUploadOptions`       | No       | Upload configuration                                                                                                                   |
| `options.pin`                   | `boolean`                | No       | Whether to pin the data locally (defaults to `false`; ignored on a subsidised gateway)                                                 |
| `options.tag`                   | `number`                 | No       | Tag ID for tracking upload progress (ignored on a subsidised gateway)                                                                  |
| `options.deferred`              | `boolean`                | No       | Whether to use deferred upload (defaults to `false`)                                                                                   |
| `options.onProgress`            | `(progress) => void`     | No       | Callback for tracking upload progress                                                                                                  |
| `options.publisher`             | `"app" \| "identity"`    | No       | Key that publishes: this origin's app key (default) or the account-wide sharing key                                                    |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                  |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole round trip, not only the Bee request |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                         |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                             |

**Returns:** `Promise<ActUploadResult>`

| Property               | Type                  | Description                                                 |
| ---------------------- | --------------------- | ----------------------------------------------------------- |
| `encryptedReference`   | `string`              | The encrypted Swarm reference (pass to actDownloadData)     |
| `historyReference`     | `string`              | The history reference (pass to add/revoke grantees)         |
| `granteeListReference` | `string`              | Reference to the grantee list                               |
| `publisherPubKey`      | `string`              | Publisher's compressed public key (pass to actDownloadData) |
| `actReference`         | `string`              | The ACT reference                                           |
| `tagUid`               | `number \| undefined` | The tag UID if a tag was created                            |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated or cannot upload
- `Error` if the request times out

**Example:**

```typescript

console.log('Encrypted Reference:', result.encryptedReference)

// - encryptedReference, historyReference, publisherPubKey
```

### `actRevokeGrantees(historyReference, encryptedReference, revokeGrantees, requestOptions?)`

Revokes access from grantees by removing them from the ACT.

:::caution[Revocation is forward-only]
Revoking a grantee **does not take back access to content already published**. While they were
granted, they held the access key, and the reference lives in immutable history — so a former
grantee can still decrypt everything published before the revocation. What revocation stops is
access to content published _after_ it.

The `encryptedReference` is deliberately **not** re-encrypted and comes back unchanged. Rotating it
would mean re-encrypting the same content under a new key, which leaks the keystream to exactly the
people being revoked ([#496](https://github.com/snaha/swarm-id/issues/496)).

If content must become unreadable to a former grantee, it has to be re-uploaded as new content
under a new ACT.
:::

**Parameters:**

| Parameter                       | Type                     | Required | Description                                                                                                                            |
| ------------------------------- | ------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `historyReference`              | `string`                 | Yes      | The current history reference                                                                                                          |
| `encryptedReference`            | `string`                 | Yes      | The current encrypted reference                                                                                                        |
| `revokeGrantees`                | `string[]`               | Yes      | Array of compressed public keys to revoke (66 hex chars)                                                                               |
| `requestOptions`                | `RequestOptions`         | No       | Request configuration                                                                                                                  |
| `requestOptions.timeout`        | `number`                 | No       | Request timeout in milliseconds for this call. Replaces the client's default (30 s) for the whole round trip, not only the Bee request |
| `requestOptions.headers`        | `Record<string, string>` | No       | Custom headers                                                                                                                         |
| `requestOptions.endlesslyRetry` | `boolean`                | No       | Whether to retry endlessly                                                                                                             |

**Returns:** `Promise<ActRevokeGranteesResult>`

| Property               | Type     | Description                                                  |
| ---------------------- | -------- | ------------------------------------------------------------ |
| `encryptedReference`   | `string` | The content reference, **unchanged** — see the caution above |
| `historyReference`     | `string` | **New** history reference, without the revoked entries       |
| `granteeListReference` | `string` | Reference to the updated grantee list                        |
| `actReference`         | `string` | The ACT reference                                            |

**Throws:**

- `Error` if the client is not initialized
- `Error` if the user is not authenticated
- `Error` if the request times out

**Example:**

```typescript
const revokeKeys = [
  '02abc123...', // Alice's public key (revoke access)
]

const result = await client.actRevokeGrantees(historyReference, encryptedReference, revokeKeys)

// The history reference is new — store it, and use it for everything from here on.
console.log('New history reference:', result.historyReference)

// The content reference is the same one you passed in. It is not re-encrypted.
console.log('Content reference unchanged:', result.encryptedReference === encryptedReference) // true
```

## Errors

Every rejection a client call produces is a `SwarmIdError`. Its `message` is the text the call always carried; `code` is the stable part to branch on, and where Bee or the gateway answered, the response is there too:

```typescript
import { SwarmIdError } from '@solarpunkltd/swarm-id'

try {
  await client.uploadData(data)
} catch (error) {
  if (!(error instanceof SwarmIdError)) throw error
  switch (error.code) {
    case 'not-authenticated':
      return showConnect()
    case 'upload-unavailable':
      // error.reason is the same vocabulary as connectionInfo.uploadUnavailableReason
      return showNoDrive(error.reason)
    case 'bee-rejected':
      return showFailed(`${error.status}: ${error.beeMessage ?? error.message}`)
    case 'timeout':
      return retry()
    default:
      return showFailed(error.message)
  }
}
```

| Code                  | Meaning                                                                                                                                                                                                                | Also set                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `not-authenticated`   | No session for this origin                                                                                                                                                                                             |                               |
| `upload-unavailable`  | The session refuses to stamp; see [Why Uploads Are Unavailable](../subsidised-gateway/#why-uploads-are-unavailable)                                                                                                    | `reason`                      |
| `partition-contended` | Every partition of the batch is held by other devices and none yielded in time                                                                                                                                         |                               |
| `lease-lost`          | This device's partition was reclaimed mid-write                                                                                                                                                                        |                               |
| `bee-rejected`        | Bee or the gateway answered with a non-2xx status. A `404` on `/bzz` and on a chunk mean different things; `url` — the request's path, never the node's host — says which                                              | `status`, `beeMessage`, `url` |
| `network`             | The request never got a response: DNS, a refused connection, or a CORS preflight the gateway rejected                                                                                                                  |                               |
| `timeout`             | A deadline ran out: the proxy's on a Bee request, or the client's on the whole round trip (`requestOptions.timeout`)                                                                                                   |                               |
| `invalid-request`     | The message or an argument failed validation                                                                                                                                                                           |                               |
| `invalid-state`       | The client cannot take the call in its current state: `initialize()` has not resolved, was already called, or `destroy()` ran. A call, or an `initialize()`, still pending when `destroy()` runs rejects with this too |                               |
| `init-failed`         | The proxy iframe did not come up: it failed to load, the proxy refused the origin, or it did not answer within `initializationTimeout`; `initialize()` rejects with this                                               |                               |
| `popup-blocked`       | The browser blocked the authentication popup `connect()` opens: not called from a user gesture, or a blocker                                                                                                           |                               |
| `button-required`     | `connect()` was called where your site's Swarm ID frame does not share Swarm ID's storage. Sign in through [`mountButton()`](#mountbuttoncontainer-options)                                                            |                               |
| `internal`            | Anything else; the message is preserved                                                                                                                                                                                |                               |

The instance is built on the client side from the fields the proxy sends — an `Error` posted through the iframe bridge arrives as a plain `Error`, so it never crosses it. An app that bundles two copies of the package should branch on `error.code` rather than `instanceof`, which is per copy.

## Avatars

Every account has an avatar, generated from its identity id — the same image Swarm ID shows for that account, so the user recognises it in both places. It is handed to you as an image at a URL rather than as markup, so the shape still holds if an avatar ever comes from somewhere other than the generator.

It arrives already resolved on every connection snapshot — there is nothing to call:

```typescript
const identity = client.connectionInfo.identity
if (identity) {
  img.src = identity.avatar.url
}
```

**`Avatar`:**

| Property | Type          | Description                                                                             |
| -------- | ------------- | --------------------------------------------------------------------------------------- |
| `source` | `"generated"` | Where the image came from. Only `generated`, derived from the identity id, exists today |
| `url`    | `string`      | Renderable as an `<img>` source; a `data:` URL for generated avatars                    |

Branch on `source` rather than assuming the URL always wraps an inline SVG — that keeps your code correct if another kind of image is ever added.

### `getAvatar(options?)`

The avatar at a specific size. Most apps do not need this — `identity.avatar` is already resolved and, being vector today, scales to any size with CSS. Reach for it when you need the image rendered at a particular pixel size. It is async so that honouring a size may involve fetching, which anything but the generated avatar would.

**Parameters:**

| Parameter      | Type     | Description                               |
| -------------- | -------- | ----------------------------------------- |
| `options.size` | `number` | Width and height in pixels (default `40`) |

**Returns:** `Promise<Avatar | undefined>` — `undefined` when no identity is connected

```typescript
const avatar = await client.getAvatar({ size: 128 })
```

### `generatedAvatarSvg(seed, size?)`

The generated avatar as a standalone SVG string, for callers that want to inline the markup instead of pointing an `<img>` at a URL. Derived from the seed alone: no network access, no other dependency.

**Parameters:**

| Parameter | Type     | Description                                          |
| --------- | -------- | ---------------------------------------------------- |
| `seed`    | `string` | Value the avatar is derived from — use `identity.id` |
| `size`    | `number` | Width and height in pixels (default `40`)            |

**Returns:** `string` — a complete `<svg>` element

```typescript
import { generatedAvatarSvg } from '@solarpunkltd/swarm-id'

const identity = client.connectionInfo.identity
if (identity) {
  document.getElementById('avatar').innerHTML = generatedAvatarSvg(identity.id, 48)
}
```

The same seed always produces the same image, so it is safe to render on every `onConnectionChange` without caching. `generatedAvatar(seed, size?)` is also exported, returning the same image as an `Avatar` with a `data:` URL.

## The identity site's entry point

Everything above is `@solarpunkltd/swarm-id`, the package root, and it is the whole surface an app needs: a `SwarmIdClient`, its types, and a few helpers for reading uploads back. The identity site (the trusted domain) imports its own half of the protocol from `@solarpunkltd/swarm-id/internal`: account state sync and the fold, key derivation, the account bus, the proxy iframe. Every function there takes the account record, the master key or `derivationKey`, none of which ever leaves the trusted domain, so an app cannot call them and nothing on the wire hands them out. That entry is not documented here; the design pages in the repository (`docs/Account-State.md`, `docs/Account-Bus.md`) and the [Key Derivation](../key-derivation/) page describe what it does. It is in the package's `exports` so the identity site can import it, with one more reader: a host that embeds the identity site and writes its `localStorage` directly, for which [Storage Layout](../storage-layout/) names the few schemas and functions to use. Beyond those, it carries no stability promise, its names move whenever the UI's needs do, and a change there is not a breaking change of the package. Do not build an app on it.
